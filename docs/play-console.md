# Play Console 내부 테스트 올리기

## 1. 출시용 파일(AAB) 만들기: 맥의 Android Studio

1. 최신 코드 받기: **Git > Pull**
2. **Build > Generate Signed App Bundle or APK** → **Android App Bundle** → Next
3. Key store path에서 **Create new...** (처음 한 번만)
   - 저장 위치: 저장소 폴더 **바깥** (예: `~/keys/jeopda-upload.jks`)
   - 비밀번호, Alias(예: `upload`), 이름 정도만 입력
   - 이 파일과 비밀번호를 잃어버리면 업데이트를 올릴 수 없으니 따로 백업
4. Build Variants에서 **release** 선택 → Create
5. 결과 파일: `app/release/app-release.aab`

> 업데이트를 올릴 때마다 `app/build.gradle.kts`의 `versionCode`를 1씩 올려야 한다 (Claude에게 요청).

## 2. Play Console

1. **앱 만들기**
   - 앱 이름: `접다 - 폴더폰 모드 런처`
   - 기본 언어: 한국어 / 앱 / 무료
2. **테스트 > 내부 테스트 > 테스터**: 본인 Gmail을 이메일 목록에 추가
3. **새 버전 만들기** → `app-release.aab` 업로드
   - Play 앱 서명: 기본값(Google이 관리) 사용
   - 출시 노트 예: `v0.1 내부 테스트: 폴더폰 홈, 숫자키 메뉴, 하루 1회 무료 해제`
4. 저장 → 검토 → **내부 테스트로 출시 시작**
5. 테스터 탭의 **참여 링크**를 S23U에서 열고 → 테스트 참여 → 플레이스토어에서 설치

## 3. 요구할 수 있는 신고서와 입력 문구

### 설치된 앱 목록 조회 (QUERY_ALL_PACKAGES)

- 용도 분류: **기기 검색 / 런처(홈 화면)** 계열
- 설명 (예시):
  > 접다는 기기의 기본 홈(런처) 앱입니다. 사용자가 홈 화면 메뉴에 넣을 앱을 설치된 앱 중에서 고르고, 스마트폰 모드에서 원래 쓰던 홈 앱을 찾아 띄우기 위해 설치된 앱 목록이 필요합니다. 앱 목록은 기기 안에서만 사용하며 외부로 전송하지 않습니다.

### 연락처 읽기 (READ_CONTACTS), 전화 걸기 (CALL_PHONE)

- 일반 위험 권한이라 별도 신고서는 없지만, 데이터 보안과 개인정보처리방침에 연락처 처리 방식을 적는다.
- 용도: 폴더폰 화면의 연락처 목록 표시, 다이얼러·연락처에서 바로 전화 걸기

### 정확한 알람 (SCHEDULE_EXACT_ALARM)

- 사용자가 직접 켜는 권한이라 별도 신고가 필요 없을 수 있다. 물어보면:
  > 사용자가 정한 스마트폰 모드 종료 30분 전·10분 전에 알림을 보내기 위해 사용합니다.

### 데이터 보안 (Data safety)

- v0.1 기준: **수집·공유하는 데이터 없음**
  - 연락처는 기기 안에서 화면에 보여주는 데만 쓰고, 저장·전송하지 않음 (Play 기준 "수집"이 아님)
  - 해제 사유, 메뉴 설정은 기기 안에만 저장, 전송 없음
  - 인터넷 권한 없음 (광고·결제를 붙이는 v0.2에서 다시 작성)

### 개인정보처리방침

- 내부 테스트에서는 요구하지 않을 수도 있다. 요구하면 아래 초안을 웹에 올리고 주소를 입력한다
  (호스팅 위치는 출시 전 결정 사항: 예) 노션 공개 페이지, GitHub Pages).

> **접다 개인정보처리방침**
> 접다는 사용자의 개인정보를 수집하거나 외부로 전송하지 않습니다.
> - 설치된 앱 목록: 홈 화면 메뉴 구성과 원래 홈 앱 실행에만 기기 안에서 사용합니다.
> - 해제 사유와 설정: 기기 안에만 저장되며, 앱을 삭제하면 함께 삭제됩니다.
> - 연락처: 폴더폰 화면에 연락처 목록을 보여주고 전화를 걸기 위해 기기 안에서만 읽습니다. 따로 저장하거나 외부로 전송하지 않습니다.
> - 전화 걸기: 사용자가 통화 키를 누른 번호로만 전화를 겁니다.
> - 통화 기록, 문자 내용, 알림 내용에는 접근하지 않습니다.
> 광고·결제 기능이 추가되면 이 방침을 업데이트합니다.

## 4. 주의

- 내부 테스트(출시용) 빌드에는 **"개발용 해제"가 없다.** 무료 해제는 하루 3회만 된다.
- 디버그 APK와 플레이스토어 버전은 서명이 달라서 함께 설치할 수 없다. 플레이스토어 버전을 설치하려면 기존 앱을 먼저 삭제한다.

## 인앱 상품 (수익 창출 → 제품 → 일회성 제품)

결제 기능이 들어간 버전(버전 코드 5 이상)을 내부 테스트에 먼저 올려야 상품을 만들 수 있다.

| 제품 ID | 이름 | 설명 | 가격 | 앱이 하는 일 |
|---|---|---|---|---|
| `refill_free_unlocks` | 무료 해제 초기화 | 오늘 무료 해제를 다시 3회로 채워요 | ₩500 | 결제 후 소비 → 다시 살 수 있음 |
| `theme_cloud_cat` | 구름 고양이 테마 | 흰 종이에 펜으로 그린 폴더폰 테마. 달빛 하늘과 구름 위 고양이가 움직여요 | ₩4,900 | 소비하지 않음 → 계속 씀, 재설치해도 복원 |

- 구매 옵션 유형은 둘 다 **구매(Buy)**. 저장 후 **활성화**
- 테스트: 설정(계정) → 라이선스 테스트에 폰 계정 추가 → 내부 테스트 링크로 설치한 앱에서 결제 ("테스트 카드, 항상 승인")
- 테마 테스트 결제를 되돌리려면: Play Console → 주문 관리에서 해당 테스트 주문 환불 → 앱을 다시 열면 테마가 기본으로 돌아감
